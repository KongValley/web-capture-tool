# 网页抓取工具

基于 Electron 的桌面抓包 / 爬虫工具：内嵌真实浏览器加载并登录目标站点，抓取**全部请求与响应体、Cookie、Storage、页面 HTML**，并提供数据提取、自动翻页、反爬伪装与多种导出格式。

专为 **Windows 7 SP1 32 位** 老机器适配（Electron 22.3.27 / Chromium 108 / ia32），同时可在 Windows 10/11 直接运行，绿色免安装。

> 完整操作手册（逐功能入口、操作步骤、产物格式、常用配方、故障排查）：[docs/manual.md](docs/manual.md)。本 README 只做功能一览。

| 反爬伪装 | UA 预设与自定义、自定义请求头注入、HTTP/SOCKS 代理 + 「**测代理**」一键验证（显示解析到的代理与真实请求状态/耗时）、请求最小间隔（礼貌抓取，0–10000ms） |
| 兼容性 | 忽略证书错误（内网自签名站点）、Basic 认证用户名/密码自动应答 |

| 抓包分析 | 记录 ★ 标记与文字备注（随会话恢复保留）；**统计概览**（按域名/类型/状态的条数·大小，最慢与最大各 top10）；**瀑布图**视图；**耗时分解**（DNS / 连接 / TLS / 发送 / 等待 / 下载六段，详情内显示，HAR 的 timings 同步填实）；**响应体全文搜索**（`body:"文本"`，扫已保存的文本响应体，命中数显示在列表上方，新记录到达自动重算）；详情里 JSON 响应体可**一键美化/还原**；**抓包快照对比**（存两个快照，按 `METHOD url` 对比出新增 / 消失 / 变化，耗时差超过 20% 才算变化） |

| 页面工具二期 | **元素拾取**（页面悬停高亮、点选即得 CSS 选择器，回填到截图 / CSS 提取的行选择器，或「拾取到字段」追加进字段行；拾取中可在提示里点「取消」）；**执行 JS**（走 CDP，不受页面 CSP 限制，带最近 10 条历史）；**一键清理运行时数据**（Cookie / Storage / 缓存 / 日志 / 会话文件 / 录制记录，逐项可选、逐项报结果） |
| 性能 | 抓包事件按 100ms 合并推送（繁忙页面不再逐事件刷面板）；列表按 id 差量同步（同一批数据重刷不重建 DOM）；请求计数增量维护；录制写盘走异步队列（停止/退出路径同步兜底）；**列表追加/过滤/重绘不再逐行读布局**（3000 行追加 34s → 0.3s）、过滤解析缓存、单元格式增量绘制；**软件渲染自动降级**全屏模糊与阴影；**会话写盘分片序列化**（不长时间卡主进程）——详见[性能与老机器适配](#性能与老机器适配) |
| 设置备份 | 设置一键导出/导入（`settings.json` 备份与迁移） |
| 会话录制 | 一键记录交互（点击/输入/变更/提交/按键/滚动）+ 请求/响应（含头与响应体）+ 导航 + WebSocket 帧，落盘 `rec-<时间戳>.jsonl` 并自动生成同名 `.md` 时间线；可选「点击截图」 |

## 环境要求

- 开发：Node.js 与 npm（本项目在 Node 24 + npm 12 下开发）
- 运行（打包版）：Windows 7 SP1 32/64 位 或 Windows 10/11，无需安装 Node

> **Windows 7 注意**：必须已安装 **SP1** 与 SHA-2 代码签名补丁（KB4474419，配套服务栈 KB4490628），否则 Electron 22 无法启动。这是 Chromium 的硬性要求，没有替代方案。

标签栏下方是面板本体：过滤框 + 类型过滤 + 列预设，请求列表 / WebSocket / 瀑布三个视图，选中行后展开详情。

## 抓取与导出

- **登录**：直接在视图里登录即可；Cookie 与 localStorage 保存在持久分区，重启后仍保持登录态。
- **导出全部**：页面数据 + Cookie + 全部请求记录（含响应体）+ WebSocket 帧，输出为单个 JSON；点「导出筛选结果」只导出当前列表里筛出来的那些记录，详情里点「导出此条」只导出单条。
- **HAR**：标准 1.2 格式，可用 Chrome DevTools 的 Network 面板直接导入查看。
- **响应体存盘**：选择目录后按 `序号_方法_主机路径.扩展名` 写入文件，重名自动追加 `-1`、`-2`，二进制响应体按原始字节写出；单条响应用详情里的「另存为文件」/「请求体另存」。
- **规则落盘**（工具栏「落盘」）：配好 URL 正则 / 类型（全部 · 仅 XHR·Fetch · 仅 Document）/ MIME 关键字（如 `json,csv`）与目标目录后开启，命中的响应体**边抓边写**到目录，并按站点目录树镜像（`site/<主机>/<路径>`：目录 URL 用 `index.<扩展名>`、查询串在扩展名前插 `_q_<hash>`，与离线包同一套命名；重名在扩展名前加 `-1`、`-2`），列表里该行标记 `已落盘：<站点相对路径>`，面板状态栏显示累计个数与体积；单次运行最多 2000 个文件 / 512MB，到顶只提示一次；改规则会重置计数。留空 URL 正则与 MIME = 全部命中。
- **重放**：在弹窗里可改写方法、URL、请求头（每行 `名称: 值`，大小写不敏感覆盖）与请求体，默认预填抓到的原始内容；结果就地展示（响应体截断到 1MB）并追加到详情面板，不会混入抓包列表。

设置项（拦截/限速/UA/请求头/代理/间隔/证书/认证）中，**拦截、UA、请求头、代理、证书、认证**刷新页面后生效；**限速、仅记 XHR/Fetch、请求间隔**立即生效。所有设置重启后保留。

### 检索语法

过滤框支持字段语法，多个条件用空格分隔且必须同时满足（AND），单个条件前加 `!` 取反：

| 写法 | 含义 |
|---|---|
| `api/data` | URL 子串 |
| `method:post` | 方法完全匹配 |
| `status:4xx` / `status:>=400` / `status:<500` / `status:204` | 状态码：`Nxx` 归类、比较符、精确值 |
| `type:xhr` | 资源类型完全匹配（XHR / Fetch / Script / …） |
| `mime:json` | MIME 子串 |
| `domain:example.com` | 主机名等于或为其子域 |
| `size:>100k` / `size:<1m` | 编码后大小，支持 `k`/`m` 后缀（1024 进制） |
| `time:>500` | 耗时（毫秒） |
| `star:1` / `star:0` | 只看已加 ★ 标记 / 未标记的记录 |
| `body:"文本"` | 响应体全文搜索（只搜已保存的文本响应体，二进制跳过），命中数显示在列表上方提示条 |

例：`type:xhr status:4xx !mime:json` = XHR 里 4xx 且响应不是 JSON 的请求。
列表右上角的列预设可切换第二列显示：耗时 / 追加类型·大小 / 时间戳（选择会随设置持久化）。

### 会话数据

工具栏「会话数据」打开管理面板：

- **Cookie**：逐条改值（`change` 即写回，失败会回滚并提示）、删除、新增（挂到当前页 origin）、导入（粘贴 `a=1; b=2` 或 JSON 数组）、导出 JSON / Netscape（`cookies.txt`，可直接给 `curl -c/-b`、wget 用）。
- **localStorage / sessionStorage**：逐项改值、删除、新增（写操作后界面重新拉取，与浏览器内实际值保持一致）；localStorage 段落另有「**导入 Storage**」，一次粘贴 JSON 对象（`{"k":"v"}`）或每行 `k=v`，逐个写入并报告成功/失败条数。
- **页面信息**：标题、URL、HTML 长度、`document.cookie`。

### 快照对比

工具栏「快照」：点「保存当前」把当前标签抓到的请求存成快照（`METHOD url` + 状态 + 耗时 + 大小，**只留在本次运行内存里，最多保留最近 2 个**，不写盘、不与会话恢复抢语义）。存两个快照后点「与上一个对比」，弹窗按 `METHOD url` 给出三张表：**新增** / **消失** / **变化**（状态不同、大小不同，或耗时差超过 `max(20ms, 20%)`；同键多条取第一条为代表并标注条数）。适合「改一次参数前后各存一次，看接口多了什么、慢了哪里」。

## 数据提取与自动化

**CSS / XPath 提取**：填入行选择器（如 `.item`）与字段（每行 `名称=选择器[@属性]`），提取结果可预览前 20 行并导出 CSV/JSON。选择器为 `:self` 时取行元素本身；`@href` / `@src` 会自动解析成绝对地址。

XPath 用 `xpath:` 前缀（行选择器与字段都支持），例如行选择器 `xpath://div[@class="item"]`、字段 `标题=xpath://span[1]`；带前缀的字段不再按最后一个 `@` 切属性（`@` 归 XPath 自己用），以 `//` 开头的字段 XPath 会改写成 `.//` 在**本行内**求值。录制与拾取都会给出该元素的 XPath（见下），需要 CSS 时用不带前缀的写法即可。

**翻页 + 提取**：提取弹窗里填好行列选择器后，设页数与间隔（可另填一个任务起始 URL，留空就用当前页），点「翻页+提取」：每页跑一遍提取、自动识别「下一页」翻页，跑完把所有页的行合并成一张表 —— 每行带 `_page` 列标明来自第几页，重复行只统计条数（提示里注明）不悄悄删掉。结果同样能导出 CSV/JSON，过程中可随时点工具栏「停止」。

**任务预设**：把「行/列选择器 + 页数 + 间隔 + 起始 URL」存成命名预设（最多 20 条，写进 `settings.json`），下次选中即回填；也可就地删除。

**页面清单**：一次性取出页面上的链接、图片、表单、表格，导出 JSON 或把表格合并导出为 CSV。

**自动滚动**：反复滚动到底并等待内容加载，连续两轮高度不再增长即停止（默认 5 轮，最大 50 轮）。

**自动翻页**：自动识别「下一页」（优先 `a[rel=next]`，其次按文案匹配），按设定的间隔翻页，最多 100 页，可随时点「停止」。

## 页面工具

- **页面查找**：工具栏「页面查找」在面板里开一条查找栏，输入即查（CDP 走 `findInPage`），显示 `当前/总数`，↑/↓ 切换上一个/下一个，`Esc` 或 ✕ 结束查找。
- **截图**：可见区域截图、整页截图（自动按内容高度扩展，不需手动滚动）、按 CSS 选择器截图（元素不存在会明确报「未找到匹配元素」）。
- **PDF**：`printToBackground` + A4 打印当前页为 PDF。
- **元素拾取**：「截图/PDF」与「CSS 提取」弹窗里都有「拾取」按钮：点击后到页面上悬停（蓝框高亮）、单击即取到该元素的 CSS 选择器（`Esc` 或提示里的「取消」都可中止），自动填进弹窗的选择器输入框；CSS 提取里另有「**拾取到字段**」，把选择器直接追加成一行字段（`名称=` 由自己补）。选择器算法与录制共用一份（`recorder.SELECTOR_SRC`）。拾取同时生成该元素的 **XPath**（唯一 id 用 `//*[@id="…"]`，否则逐级 `/tag[n]`）：提示条里点「复制 XPath」即可取走；录制中的实时条目把 XPath 放在悬停提示里（点击仍复制 CSS 选择器）。
- **执行 JS**：「执行 JS」弹窗把命令送进当前页面的主世界执行（走 CDP，不受页面 CSP 限制），返回 JSON 结果或错误信息；最近 10 条命令留在下拉历史里（仅内存）。
- **清理数据**：「清理数据」弹窗可勾选 Cookie / Storage / 缓存 / 日志 / 会话文件 / 录制记录，逐项执行、逐项报结果；清理 Cookie / Storage 会让相关站点退出登录，操作立即生效且不可撤销。
- 前三者都在「截图/PDF」弹窗里操作，完成后 toast 出落盘路径。

## 会话恢复与日志

**会话恢复**：抓包过程中每 30 秒（记录有变化时）与退出时把最近 2000 条记录（含响应体，总量上限 64MB，超出部分省略响应体并标注原因）与 WebSocket 帧写入 `<userData>/sessions/last.json`。下次启动若文件在 7 天内，面板顶部横幅提示「发现上次会话」：点「恢复」把记录灌回列表（编号续接，新的抓包不会与旧记录冲突），点「忽略」直接删除该文件。

**诊断日志**：`<userData>/logs/app.log`，超过 2MB 滚动为 `app.log.1`（只保留一代）。记录启动失败、渲染进程退出、证书错误、认证请求、IPC 异常与未捕获异常/未处理 rejection；未捕获异常只记日志并在状态栏提示，**不会退出进程**。工具栏「设置」里可直接查看最近 1000 行（可关键字过滤）并打开日志所在文件夹。

## 无显卡 / 老旧机器

工具会读取 Chromium 上报的 GPU 状态：若没有可用的硬件加速（驱动缺失、显卡过老、虚拟机、远程桌面），会自动开启软件渲染并在面板顶部给出提示条，点「立即重启」即可生效。GPU 进程反复异常退出时同样会触发。

- **核显照常走硬件加速**（Intel HD/UHD、AMD APU 等），不会被判定为「无显卡」。判定依据是 Chromium 实际上报的合成状态，与是否独显无关。
- 判定采用**双次采样**：启动瞬间的状态可能是瞬时的，两次采样都判定为软件渲染才会写入配置，避免误改。
- 也可手动控制：工具栏「设置」里勾选「强制软件渲染」，或在命令行加 `--software-rendering`。

「设置」对话框中还会显示当前 `gpu_compositing` 原始值、判定结论与 GPU 进程异常次数，便于排查。

## 会话录制

点工具栏「● 开始录制」开始，按钮实时显示时长与已记录条数、面板顶部同步显示最近 20 条录制项；再点「■ 停止录制」结束，状态栏常驻产物路径（点击可复制），工具栏「打开摘要」可随时定位最近一次录制的 `.md`。录制期间记录：

| 类型 | 内容 |
|---|---|
| 交互 | 点击（CSS 选择器、**元素标签链与类型**、文案、坐标、链接）、输入 / 变更（值、**元素标签链与类型**，密码框一律写成 `[password]`）、表单提交（action/method/字段）、特殊按键（带元素标签）、滚动（500ms 节流） |
| 网络 | 每个请求的方法 / URL / 类型 / 请求头 / 请求体，响应状态 / MIME / 大小 / 耗时 / 响应头，以及响应体 |
| 导航 | `did-navigate` / 页内跳转 / 加载失败，以及每次页面加载完成后的标题 |
| WebSocket | 建立 / 发送 / 接收 / 关闭 / 错误帧 |
| 关联 | 交互后 2 秒内发出的请求会带 `after: <交互条目的 n>`，直接把「点了什么 → 发了什么」串起来 |

产物写在 `<userData>/recordings/`（打包版 `%APPDATA%\web-capture-tool\recordings\`）：

- `rec-<时间戳>.jsonl`：每行一个 JSON 对象，`k` 为类型（`manifest` / `action` / `req` / `res` / `body` / `nav` / `page` / `ws` / `shot` / `note` / `summary`），首行是清单（版本、UA、视口、起点 URL、当时的抓取设置），末行是汇总（条数、时长、停止原因）；`action` 行带 `sel`（CSS 选择器）、`xpath`（同元素的 XPath）与 `tag` / `chain` / `type`（元素标签、标签链、input 类型）。
- `rec-<时间戳>.md`：人类可读的时间线摘要，每行末尾带该动作元素的 **CSS 选择器（可直接复制去写爬虫：`querySelectorAll` / parsel / Playwright 都能用）**，例如
  ```
  [00:00.006] #3 点击 a ← div.item ← body ← html「linkA」 (0,0) · html > body > div.item:nth-of-type(1) > a
  [00:00.008] #3 └→ GET /a · 404 · - · 0B
  [00:00.016] #3 ⇢ 跳转 /a
  ```
  最多输出 500 行并注明总数；进程被杀/断电时只有 `.jsonl`（此时无 `.md`）。
- 录制过程中面板顶部的「最近 20 条」也能直接取用：**点任意一条即把它的 CSS 选择器复制到剪贴板**（悬停显示完整选择器）。
- 勾选「点击截图」后每次点击额外存一张视口 PNG（`rec-…-click-001.png`，单次录制上限 300 张），文件名写进 JSONL 的 `shot` 行。

体积边界：单条文本响应体 256KB、单次录制响应体总量 32MB、请求体 8KB、单帧 WebSocket 4KB、总条数 10 万（到达即自动停止并提示）。二进制响应体会按原样写入 base64。录制期间会自动打开抓取（停止后恢复原来的暂停状态）；交互记录不受暂停影响，网络记录则受。

### 录制历史与重放

工具栏「录制历史」列出录制目录里的 `.jsonl`（按时间倒序，显示条数/大小/停止原因），右侧显示同名 `.md` 时间线（可用关键字逐行过滤），并提供：

- **重放**：在当前活动标签里按录制顺序重演交互动作（点击 / 输入 / 值变更 / 提交 / 按键 / 滚动）。倍速 1× / 2× / 4× 或不等待（会有弹窗实时显示进度），「失败即停」默认勾选，也可随时点「停止重放」。默认**不回放导航**（跳转由点击/提交自然发生），勾选「重放导航（跳转页面）」后会按录制顺序执行 `nav` 步骤；跳过导航的步数会在结果里注明。密码输入在录制时被掩码成 `[password]`，重放时记一条失败而不猜值。
- **删除与占用**：历史弹窗顶部显示目录总占用（`.jsonl` + `.md` + 点击截图，超过 1GB 会提醒），「删除此条」会二次确认后删掉该次录制的全部文件；「清理数据」里也有「录制记录」一项可一键清空目录内产物（保留目录本身）。
- **导出回放脚本**：生成独立的 Playwright 脚本（`replay-<录制名>.js`），附使用说明注释；密码行写成空值并在上方注释提示手动填写。

重放只作用于**当前活动标签**，CDP 未就绪时直接报错；单个录制最多回放 2000 个动作、读取最多 5000 个动作（长录制请分段）。

## 性能与老机器适配

面板列表是这套工具里唯一会随请求数线性变重的地方，因此针对老机器做了三处结构性优化（都不是"少画几行"式的妥协，行为完全不变）：

| 位置 | 原来 | 现在 |
|---|---|---|
| 列表追加（每行） | 每追加一行都读一次 `scrollHeight` 并把 `scrollTop` 写到最大 → **每行一次强制同步布局**，3000 行列表下实测 34s | 跟随状态缓存 + 一轮任务只写一次滚动位置：3000 行 0.3s（≈115×） |
| 抓包事件批（100ms） | 一批里每行都走上面那步；一页几百个请求时面板卡死数秒 | 同上，1000 行 0.15s（≈226×） |
| 过滤框输入 | 每敲一个字把 3000 行**整行重画**（改文本 + 属性） | 只重算可见性（不碰行文本）+ 过滤串解析结果缓存：38ms → 5ms（≈8×） |
| 列预设切换 | 逐行重写全部单元格与 `data-*` 属性 | 只写变化的单元格；列表级 `data-cols` 只写一次：34ms → 4ms |

其余针对弱机器的处理：

- **抓包 IPC 减半**：同一请求的两条 `responseReceivedExtraInfo` 只在状态真的变化时推给面板（原始响应头本来就在详情里按需读取）。
- **会话写盘不再长时间阻塞**：`sessions/last.json` 的序列化按 200 条分片、片间让出事件循环（原来一次性 `JSON.stringify` 几十 MB，主进程连带面板一起卡住，老机器上到秒级）；退出路径仍走同步写，保证进程随时消失也不丢。
- **软件渲染自动降级**：检测到无显卡 / 强制软件渲染时，面板自动关掉全屏 `backdrop-filter` 模糊与模态/提示/右键菜单的阴影（这几项在纯 CPU 合成下是每帧重绘的大头）。
- **列表改为窗口化渲染（虚拟滚动）**：DOM 只保留滚动窗口内的行（约 `视口高度 / 26 + 16` 行），行/分组标题绝对定位、`#listInner` 只提供总高度，因此条数再多也不影响滚动与渲染；内存与导出口径不变（导出、复制、详情、瀑布图都按内存里的全部记录算）。

### 基准（bench）

```bash
npm run bench           # 硬件加速下的基准
npm run bench:sw        # 软件渲染（等价于无显卡机器）
WCT_BENCH_N=1200 npm run bench   # 换负载（默认 800 个并发请求）
```

基准会在本机起一台压力服务器、驱动真实窗口，打印环境（CPU / 内存 / 是否软件渲染）与这些数字：突发请求的墙钟与**主进程 CPU**、面板渲染完成时间、追加 3000 行 / 批处理 1000 行 / 1000 条更新 / 过滤 / 列预设 / 排序 / 分组耗时、面板与主进程内存、会话序列化与写盘耗时。

> 绝对值随机器变化，**对比优化前后请在同一台机器上跑**。基准里有一项「其中本地测试服务器」是用 `net.request` 直读同一批 URL 的对照值，主进程 CPU 减去它大致就是抓包链路本身的成本。

开发机（Ryzen 7 3700X / 硬件加速）实测，同一份代码优化前后：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 追加 3000 行 | 34 315 ms | **303 ms** |
| 批处理追加 1000 行 | 33 057 ms | **147 ms** |
| 过滤（输入一次） | 38.3 ms | **4.7 ms** |
| 切换列预设（重画） | 34.1 ms | **3.9 ms** |
| 按大小排序（重排） | 32.5 ms | **8.9 ms** |
| 突发 800 请求（主进程 CPU） | 1313 ms | 1297 ms |

> 主进程 CPU 这两列都包含本机测试服务器自身的开销（对照值在 bench 输出里单列，约 0.7s），差额在噪声范围内——这一轮没动抓包链路的成本，动的是面板。

列表改为窗口化渲染（虚拟滚动）之后，在同一台机器（Ryzen 7 3700X / 硬件加速）复测：追加 3000 行 **0.94 s**、批处理追加 1000 行 **0.29 s**、1000 条更新 **0.04 s**、过滤（输入一次）**13 ms**、切换列预设 **1 ms**、按大小排序 **11 ms**、域名分组 **22 ms**；面板 DOM 恒定 **约 33 行**（内存 804 行、面板内存 9.5MB）。逐条追加比上表的 303 ms 慢（每行都要维护窗口边界），换来的是**条数不再影响滚动与渲染**；突发请求的主进程 CPU 与内存口径未变。

同一台机器上 `npm run bench:sw`（软件渲染，等价无显卡机器）复测窗口化渲染后：追加 3000 行 934ms、批处理 1000 行 291ms、1000 条更新 40ms、过滤 13.3ms、列预设 1.8ms、按大小排序 11.1ms —— 与硬件加速基本持平（差距在噪声内），说明瓶颈已经从「合成」挪到了纯 JS/DOM 那一段。

## 配置文件

- 打包版与开发态一致：`%APPDATA%\web-capture-tool\settings.json`（目录名取自 `package.json` 的 `name`，`npm start` 与打包版用同一个）

  extract.js           页面侧采集：HTML/Storage/CSS+XPath 提取/页面清单
  picker.js            元素拾取器：页面高亮与点击回传，选择器算法复用 recorder.SELECTOR_SRC

  renderer.js          面板逻辑（标签栏/列表/详情/模态框/快捷键/轻提示）

依赖方向单向：`src/` 里所有模块只 `require('./state')`，任何模块都不 require `main.js`；`ui/renderer.js` 不 require 任何项目模块（只经 IPC 与主进程通信）；`dev/` 里的工具通过 `main.js` 注入的模块干活。

打包与测试用到的路径：入口 `main.js`（`package.json` 的 `main`）、面板 `ui/index.html`、图标 `build/icon.ico`，自检/基准在打包版里从 `dev/` 加载。

## 已知限制

- `userData` 目录名取自 `package.json` 的 `name`：开发态（`npm start`）与打包版**同为** `%APPDATA%\web-capture-tool`，配置、Cookie、录制产物互通。
- Cookie、localStorage 等站点数据位于 `userData` 的持久分区内，清理该分区会同时清掉登录态。
- 抓取记录上限 5000 条/标签、单条响应体 32MB、响应体总量 256MB、WebSocket 帧 2000 条，超出后按策略截断或丢弃并给出提示。
- 会话恢复只覆盖最近的标签布局（最多 5 个标签的 URL，在后台重新打开）与记录 / 标记 / 备注，不还原页面内容与表单状态。
- UA / 请求头 / 限速这三项设置作用于**当前活动标签**的视图；新建标签会沿用设置，但已存在的后台标签不会跟着改。
- 后台标签关闭了 `backgroundThrottling` 以便继续抓包与自动翻页，代价是标签越多 CPU 占用越高。
- 页面内查找的匹配计数始终准确；高亮是否可见取决于页面视图当前是否拿到焦点（被遮挡时可能看不到高亮，这是 Chromium 的渲染策略）。
- 关闭标签的「撤销」恢复的是**新视图 + 原抓包记录 + 原 URL**：浏览历史、页面滚动与表单状态不恢复；撤销窗口 10 秒，只保留最近一次关闭。
- 列表按窗口渲染（虚拟滚动）：DOM 只保留可见窗口的行，滚动时行节点会复用重建（出现极短暂的空白属于渲染节奏，不是丢数据）；导出、复制、统计、详情始终按内存里的全部记录算。
- 抓包事件按 100ms 合并推送到面板：列表行最多晚 100ms 出现（切标签与「清空」会立即冲刷）；同一记录在同一批里只保留最后一次更新。
- 列表按 id 差量同步：切标签时两个标签的记录编号不重叠，等价于全量重建；收益出现在「同一批数据重刷」（会话恢复、重复的标签切换通知）时不再重建 DOM，滚动位置与悬浮状态得以保留。
- 响应体全文搜索只覆盖已保存的**文本**响应体（二进制与未捕获的跳过）；改过滤条件后 300ms 重算命中集合。
- 「清理数据」立即生效且不可撤销；清理 Cookie / Storage 会让相关站点退出登录。
- 窗口不带系统菜单栏（Electron 默认菜单已移除）：页面缩放（`Ctrl+0` / `Ctrl+±`）不再有快捷键，文本框的 `Ctrl+C/V/X/A/Z` 是 Chromium 原生编辑命令，不受影响。
- 录制写盘走异步队列：极端崩溃（断电/杀进程）最多丢最后 250ms 的事件；正常「停止录制」与退出路径会同步把残留写完。
- WebSocket 视图的「清空显示」只清界面：`state.wsFrames` 不动，切标签或改过滤条件会重新载入帧。
- 会话恢复只会把记录灌回当前标签，保存时的标签布局在后台重新打开（不抢当前标签，页面内容不还原）。
- 「忽略证书错误」只影响本次运行内的连接判定，不改动系统证书库。
- 站点要求 Basic 认证且设置里未填用户名时，会取消请求并在状态栏提示（不弹系统输入框）。
- 「测代理」会给当前站点真发一次请求（10s 超时）验证出口；解析到的代理来自 `resolveProxy`，是否真正可用取决于代理服务本身。
- 下载不接管保存路径：文件按 Chromium 默认落到系统下载目录（`app.getPath('downloads')`），工具只提示进度与结果；`--selftest` 运行时会改道到临时目录。
- 快照对比只保留**本次运行内存**里最近 2 个快照（重启即清空），且按 `METHOD url` 归组：同一 URL 的多次请求取第一条作代表并标注条数，三张表每张最多列 100 行（总数仍照实显示）。
- 列表排序 / 域名分组改为重建渲染顺序表（不再移动 DOM 节点）：内存里（导出、编号、会话恢复）始终按时间顺序；流式追加 / 更新时顺序表按 100ms 合并重建一次，用户切换排序或过滤立即生效；分组只覆盖过滤后的记录，标题条数就是该主机的实际条数（与窗口显示多少行无关）。
- 规则落盘按站点目录树镜像到目标目录（`site/<host>/<路径>`，与离线包同一套命名，查询串用 `_q_<hash>` 区分），单次运行上限 2000 个文件 / 512MB，到顶后不再写并提示一次；改规则或重启重置计数。
- 耗时分解里的「下载」= 该请求总耗时 − 首字节时间，包含排队、主进程与渲染开销，不是纯传输时间；连接复用（keep-alive）时 DNS / 连接 / TLS 三段为 0。
- Mock 开启期间会给所有标签关闭 HTTP 缓存，并临时摘掉 `webRequest` 拦截器（否则 Electron 会丢掉本地应答的状态码与响应头，只保留响应体），因此**资源阻断与请求最小间隔在 Mock 期间暂停生效**；关闭 Mock 后恢复。Mock 与其它抓包功能互不影响，未命中规则的请求一律原样放行。规则最多 30 条，按顺序匹配、第一条命中生效，改规则或开关会重置命中计数。
- Storage 批量导入只写 localStorage；sessionStorage 仍是逐项编辑（导入按钮按同样写法即可扩展）。
- XPath 只在**数据提取**（行选择器与字段，`xpath:` 前缀）与录制/拾取的记录里使用：请求重放、回放脚本导出与截图仍按 CSS 选择器定位（保持一份实现）。
- 列表「是否在底部」的判定仍是缓存的（只在滚动事件与显式失效时重算一次），但总高度改由「条数 × 26px」直接算出，不再读 `scrollHeight`：一轮连续追加里最多读一次 `clientHeight`，这是老机器上列表不卡的关键。
- 会话写盘（每 30 秒、有记录变化时）现在分片序列化，不再长时间卡住主进程；但**退出路径**仍是同步写，超大会话（几十 MB 响应体）在退出时会多停一小会儿，换来的是「随时关窗也不丢」。
- 系统保存/目录对话框需要人工点选，无法纳入自动化测试。
